# Repository working instructions

## Read before work

Read NATIVE-STATUS.md, NATIVE-BATCH-PLAN.json, the relevant requirement contract,
CHANGELOG.md and current git status. Inspect evidence before trusting historical
conversation or journal text. Work in native-sequoia-development; preserve local
changes. User instructions override these conventions.

## Documents and evidence

- NATIVE-CONTRACT.md and WPA3-CONTRACT.md define required behavior, not a diary.
- NATIVE-STATUS.md is the current implementation/evidence map. Distinguish
  implemented, locally tested, hardware observed, unverified and not implemented.
- NATIVE-CALLBACK-MATRIX.json is generated by scripts/audit-native-callbacks.py;
  edit the generator and regenerate, never hand-edit generated classifications.
- NATIVE-BATCH-PLAN.json contains current grouped work and remaining gates.
- NATIVE-CONNECTION-AUDIT.md records dated findings; docs/history preserves old
  investigations. Old unsupported/uninstalled statements are historical.
- CHANGELOG.md records meaningful integrated changes. Update affected documents
  together with code, including build UUID, exact evidence and limitations.
- PMF and SAE already exist. Pending AP-driven rekey/group BIP evidence is not
  permission to reimplement them or claim they are absent.
- A remaining integration gap must name the exact missing behavior (for example,
  the macOS pairwise-rekey completion notification), not reopen the whole feature.
  Every completed batch must reconcile requirements, status, plan and changelog.

## Work and regression policy

Handle complete related groups: contracts, implementation, cancellation, errors,
ownership and tests together. Keep intermediate edits local. No per-fix commits
or pushes; publish reviewed batches to avoid consuming GitHub Actions quota.
Previously implemented features use one consolidated regression entry point:
`python3 tests/run-development-tests.py --cxx clang++` / `make test-development`.
Run the full suite after final batch changes. Repeat only for new changes,
failures or specific unresolved concerns. Do not repeatedly benchmark closed
scan/boot stages or ask whether reboot succeeded. Passing tests prove their
scope, not untested hardware or all operating systems.

## Product and hardware boundaries

Deliver only a native OpenCore kext: no companion app, login agent, OS patches
or OpenCore Legacy Patcher dependency. Never advertise an unsupported capability.
Only one router is available: implement roaming using recovered OS behavior and
production-path fixtures; mark physical inter-AP interoperability unverified.
macOS 11–26 and AWDL/AirDrop are separate unfinished stages. Sleep is deferred
and labelled “Possibly working”; do not initiate sleep tests.
Verify candidate signature/dependencies and SD rollback before installation.
Reboot only after explicit user approval through the question form, with a
10-second delay. After reboot verify loaded UUID instead of relying on version.
Never expose passwords, keys or secret-bearing dumps in documentation or logs.
